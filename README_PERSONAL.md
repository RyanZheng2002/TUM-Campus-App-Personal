## Course details

The native course page reads the public TUMonline website endpoint:

```
https://campus.tum.de/tumonline/ee/rest/slc.tm.cp/student/courses/{courseId}
```

Calendar URLs use `lv.detail?cLvNr=...`; this explicit course ID is also accepted.
Course offering IDs (`stp_sp_nr` / `pStpSpNr`) are distinct from legacy `LvNr`
and meeting `pTerminNr` IDs. The resolver supports absolute and relative current
course links, desktop fragment links and explicit redirects from old course
pages. Meeting pages are read with GET and their explicit course link is used.
No course is selected by a guessed title or by substituting a meeting ID.
Public requests use a separate HTTP client without the app token.

The disabled legacy details API is no longer called by this page. Loading,
success and failure are exclusive states. On failure the page shows only the
error and retry button; previous details and calendar fallback text are cleared.
Successful responses must contain the requested course ID and a real title.
Responses are cached in memory for six hours by ID and language; retry bypasses
the course-response cache. HTTP failures retain their status code where available.

The page organizes verified data as:

1. Actual course title and type.
2. Selected calendar meeting: time, cancellation status and room links.
3. Course number, semester, language, SWS and ECTS when present.
4. Overall course teaching team and responsible organisation.
5. Expandable contents, objectives, prerequisites, method, assessment and notes.
6. Official TUMonline course link.

The teaching team belongs to the course and is not a claim about the instructor
of an individual meeting. SWS are never relabeled as ECTS. Missing optional
fields are omitted. Calendar technical descriptions such as `fix; Abhaltung;`
are not shown as course content. Course title and text follow the app locale,
using available official text when a translation is absent.

Each room opens `https://nav.tum.de/search?q=...`, using the full room code from
the location, e.g. `5506.01.639` or `4153.EG.001`. Without a full code it searches
the original location text.

Live verification on 2026-10-20 confirmed the supplied course `950944244`
(German as a Foreign Language B1.1), winter 2026/27, 3 SWS, five course teachers,
contents and objectives, with no ECTS supplied. The supplied meeting `893029371`
also resolved to the correct course `950945432` (Hypersonic Flows), 2 SWS.
V4 missed the `lv.detail?cLvNr=...` calendar URL format documented in upstream
Campus-iOS CalendarEvent.swift. V5 adds it to direct ID parsing and course grouping.
The obsolete lv.detail browser route returns 404, so external course links now
use the current desktop course page.

Personal enrollment lists still use the upstream authenticated service and its
existing calendar-based recovery list. This change restores public course
details and does not replace authenticated enrollment APIs.

## Personal Android build

Version: `5.3.1+5`. Package: `de.tum.in.tumcampus.personal`. Label:
`Campus Personal`. Minimum Android 10 / API 29; compile and target SDK 36.
Personal builds disable upstream Firebase initialization, Crashlytics and remote
configuration using both build switches below.

The user-supplied artwork is preserved in
`assets/branding/personal_app_icon.png`. Legacy, round and adaptive Android icon
resources are generated by `tool/GenerateAndroidIcons.java`. The adaptive icon
keeps the artwork within Android's safe area.

Requires Flutter 3.47.7 / Dart 3.13.5, JDK 21, Android platform 36,
build-tools 35.0.0 and NDK 28.2.13676358. From PowerShell:

```powershell
./tool/build_personal.ps1 -Flutter C:/path/to/flutter/bin/flutter.bat
```

Or:

```sh
export CAMPUS_PERSONAL_BUILD=true
flutter pub get
flutter test
flutter build apk --release --dart-define=PERSONAL_BUILD=true
```

Keep the local signing key for compatible updates. The supplied APK uses the
same local development certificate as V1 and V2. Do not commit the key.
The source archive excludes local toolchains, caches and signing secrets.

### Android live integration test

With an Android device or emulator connected:

```sh
flutter drive --driver test_driver/integration_test.dart --target integration_test/course_details_live_test.dart --dart-define=PERSONAL_BUILD=true --keep-app-running -d emulator-5554
```

Set `COURSE_ANDROID_SCREENSHOTS` to an output directory to retain the native
screenshots. The test mounts the production LectureDetailsView and performs
real public HTTPS requests through its production ViewModel and service.
Its calendar XML uses the documented cLvNr format and synthetic meeting
metadata; no enrolled account or HTTP fixture is injected.
